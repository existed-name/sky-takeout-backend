## RequestParam 使用 @NotBlank 检验无效

1. 测试接口

    ```java
        @ApiOperation( "对具体地址进行地理编码" )
        @GetMapping( "/geocoding" )
        public Result< GeoCodingDTO > geoCode(
                @RequestParam( name = "address", required = true )
                @NotBlank( message = "具体地址不能为空" )
                String address
        ){}
    ```

2. 问题现象
    * 如果我ApiFox不带address、就可以全局异常处理器捕获RequestParam抛出的异常然后输出信息 `请求参数 address 不能为空`
    * 如果带了address参数但是不赋值、他不能提醒 `具体地址不能为空`
3. 原因
    * 又忘了规则
    * 字段的检验注解默认不生效、需要给包装这个字段的类补上 `@Validated/@Valid` 检验注解
    * 而 `@Valid` 用于方法 dto 参数、Controller 用 `@Validated`
    * 于是给 Controller 补充 `@Validated` 就好了

    * `uri = https://api.map.baidu.com/geocoding/v3?address=%E5%8C%97%E4%BA%AC%E5%B8%82&ak=我的ak&output=json`
    * Ctrl + 单机 → 进入 Edge → 地址栏显式正常的 `https://api.map.baidu.com/geocoding/v3?address=北京市&ak=我的ak&output=json`
    * 如果直接把 uri 丢给 ApiFox 是没问题的、正常响应

4. 突然发现那个异常信息
    * `Target host is not specified` 
    * 再来看日志输出 `uri = /https://api.map.baidu.com/..`
    * uri 是 `/` 开头的

    * 也就是我的完整 URL 被当作了后面的 Path

    * 再查资料, 确实

      - 而 setPath 就只设置了 Path 这部分
6. 于是改为构造器传 url 就解决了报错



## 续上面: 地理编码测试接口无响应数据

1. 问题描述
    * 测试接口 `/test/baidu-map/geocoding?address=`
    * 对任意输入地址、输出都不带数据

    ```json
    {
        "code": 1,
        "msg": null,
        "data": {}
    }
    ```

2. 猜测是解析 json 字符串没把字段映射过来
    * `data` 不是 null 而是 `{}` 说明 dto 已经 new 出来了、但是内部字段为空
    * 注意地理编码响应 json 经纬度是嵌套的 result.location.lng/lat , 可能需要 objectMapper.readTree 拿到节点然后找出这 2 个值
    * 先给 dto 补上 `@JsonProperty( "xxx" )` 显式映射字段名称

    ```java
    /** 状态码，0 为正常 */
    @JsonProperty( "status" )
    private int status;
    /** 异常信息, 只在服务状态码异常（非0）时返回 */
    @JsonProperty( "msg" )
    private String msg;
    /** 精度 lng */
    @JsonProperty( "lng" )
    private float longitude;
    /** 维度 lat */
    @JsonProperty( "lat" )
    private float latitude;
    ```

3. 初步测试 
    * `address = 1`

    ```json
    {
        "code": 1,
        "msg": null,
        "data": {
            "status": 1,
            "msg": "Internal Service Error:无相关结果",
            "lng": 0.0,
            "lat": 0.0
        }
    }
    ```

    * `address = 北京市`

    ```json
    {
        "code": 1,
        "msg": null,
        "data": {
            "status": 0,
            "msg": null,
            "lng": 0.0,
            "lat": 0.0
        }
    }
    ```

4. 看来解析 json 只能映射最外层的字段、嵌套的话需要 readTree 读取节点
    * 不过我在想 dto 里面既有最外层字段( 可以直接映射 )又有内部的字段、该怎么比较好的一次性映射到位
    * 不过 objectMapper.readValue 已经可以把整个 json 映射过来了、只要内部类和字段定义完整就行
    * 于是完善 dto 对齐百度地图响应数据结构、拿到 result.location、现在能够正常获取 status、msg( 如果异常 )、result( 如果正常 )
