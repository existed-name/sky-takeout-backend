## Mapper 查询字段包装为 record 出错

1. 背景: 需要用 2 ~ 3 个字段, 
    * 查整个对象会浪费、
    * 每个字段单独 1 个 Mapper 方法虽然清晰但是会多查几次、
    * 又不想定义 DTO 感觉复用性可能不高且不想维护
2. 于是查资料，给 OrderMapper 定义了内部 record, 用来封装需要的 2 ~ 3 个字段

    ```java
        /**
         * 记录订单状态、支付状态, 只查询 2 个字段, 由于不确定复用性、暂时不单独新建 dto
         * @param status 订单状态
         * @param payStatus 支付状态
         * @CreateTime 2026/8/30 10:48
         */
        public record OrderStatusAndPayStatus( Integer status, Integer payStatus ){}
    ```

3. 然而报错反射错误

    ```text
    2026-08-30 11:00:45.939 ERROR 5152 --- [nio-8080-exec-7] com.sky.handler.GlobalExceptionHandler   : MyBatis 异常, 可能是 mapper 写错代码: nested exception is org.apache.ibatis.reflection.ReflectionException: Could not set property 'status' of 'class com.sky.mapper.OrderMapper$OrderStatusAndPayStatus' with value '1' Cause: java.lang.IllegalAccessException: Can not set final java.lang.Integer field com.sky.mapper.OrderMapper$OrderStatusAndPayStatus.status to java.lang.Integer
    ```

    * 问 ai 是因为我这个 mybatis 版本不够
      -`<mybatis.spring.version>2.2.0</mybatis.spring.version>`
      - 只有 MyBatis 3.5.7 的样子
      - 而 record 记录的 final 字段, mybatis 通过反射 set 字段失败
      - 到 MyBatis 3.5.10 才原生支持 record、用构造器创建 record
      - 低版本 mybatis 只能手动显式配置构造器映射 record
4. 补上这个配置也不行

    ```yaml
    mybatis:
      configuration:
        # 而且会警告 Cannot resolve configuration property 'mybatis.configuration.arg-name-based-constructor-auto-mapping'
        arg-name-based-constructor-auto-mapping: true
    ```

5. 于是切换成内部接口类记录 getter

    ```java
        interface OrderStatusAndPayStatus{
            int getStatus();
            int getPayStatus();
        }
    ```

    * 虽然编译器冒红 `Statement with id="getStatus 和 getPayStatus" not defined in mapper xml `
    * 但是可以通过编译
    * 只是如果 id 对应的订单存在, 会报错 
    * `MyBatis 异常, 可能是 mapper 写错代码: nested exception is org.apache.ibatis.reflection.ReflectionException: Error instantiating interface com.sky.mapper.OrderMapper$OrderStatusAndPayStatus with invalid types () or values (). Cause: java.lang.NoSuchMethodException: com.sky.mapper.OrderMapper$OrderStatusAndPayStatus.<init>()`
6. 给出用接口装 getter 的 AI 又说必须自定义 ObjectFactory 才可以用这个写法
    * 默认还是反射、setter 设置属性
7. 老老实实回归 dto
    * 如果给 Mapper 内部定义 dto 类, 感觉不太规范( 虽然不一定复用、而且主要是为了传字段 )
    * 新建 dto 又感觉没必要、有点麻烦、复用性不高
    * 而且主要 dto 容易混合前端传参、后端内部数据传递
8. 于是再查资料有哪些对象
    * 除了已知的 Result / vo 给前端看、dto 前端拿给后端
    * BusinessObject: 通常包含业务方法( 充血模型 ), 装字段、不带方法也行
    * DataObject: 与数据库表对应的对象
    * Projection: 查询投影, 装 mapper 查出来的字段, 但是国内可能用的不多??
    * 算了、先找个最合适的 projection
