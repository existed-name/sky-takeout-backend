## 订单管理

### 业务分析

1. 用户选完菜品、套餐，点击 `去结算` 进入订单生成提交界面
    * 选择收货地址
    * 选择收货时间段
    * 展示所有商品
      - 套餐: name + amount
      - 菜品: name + flavor + amount
    * 打包费
    * 配送费
    * 备注
    * 餐具数量选择
    * 发票选择
    * 商品总金额 + 打包费 + 配送费 = 总价 → `去支付`
2. 进入订单支付界面
    * 支付剩余时间
    * 支付总金额
    * 订单号
    * 选择支付方式
    * `确认支付`
3. 下单成功界面
    * 下单成功
    * 预计 xxx 到达
    * `返回首页`、`查看订单`
4. 订单内容(参考外卖单)
    * 支付状态(已支付)
    * 下单时间
    * 备注
    * 商品列表: 菜名、数量、小计
    * 其他费用列表: 打包/配送、数量、小计
    * 订单总金额
    * 收货地址(具体地址，不需要省市区)
    * 用户昵称、性别(先生/女士)、手机号


### 相关接口 + 思路

#### 生成订单

1. 选择地址
    * 先看有无默认地址，暂时用默认地址，GET + `/user/addressBook/default`
    * 用户手动点击的话就跳转到地址簿管理界面，GET + `/user/addressBook/list`
    * 然后选择地址，GET + `/user/addressBook/{id}` 拿到 id 给前端存着，之后整合成订单发给后端
    * 思路: 
      - 最开始我想 POST + `/user/order/addressBook/{addressBookId}` 
      - 但是发过来怎么记录这个 addressBookId??
      - order 表里面? 需要创建 order 对象，但是字段不齐
      - 订单和其他对象的关联关系表?? 但是缺少关联订单 id
      - 所以还是先交给前端，之后收齐数据发给后端
2. 选择收货时间段
    * 交给前端记录数据
3. 展示所有商品
    * GET + `/user/shoppingCart/list`
4. 备注
    * 可选
    * 交给前端记录数据
5. 餐具数量选择、发票选择
    * 交给前端记录数据
6. 总金额
    * 打包费、配送费: 
      - GET + `/user/order/PackingFee` 以及 `DeliveryFee`
      - 思路: 后端特定计算逻辑(根据商品数量、价格 + 店家要求)
    * 总金额:
      - GET + `/user/order/totalAmount`
      - 总金额 = 商品总价 + 打包费 + 配送费
7. 生成订单
    * POST + `/user/order` + @RequestBody OrderDTO 
    * 或者不存进 order 而是 temp_order, unpaid_order ??
    * DTO = id + addressBookId + period + List< Long > shoppingCartIdList + 
      - remark 备注 + tablewareNumber 餐具 + invoice 发票 + totalAmount
    * 思路: 
      - Controller 方法参数检验
      - DTO 转 entity
        + 设置 userId
        + 设置支付剩余时间(订单有效时间): 不过如何前端、后端实时同步展示时间变化???
        + 设置订单号: 特定业务规则字符串拼接(商家前缀 + 日期 + 时间 + 用户标识……) | 随机 UUID 生成
      - 但是怎么存 shoppingCartIdList ?
        + 考虑关联关系表: shoppingCartId + orderId ?
        + 但是我觉得每次下单(或者支付成功后)应该清除用户购物车数据,那就不能存购物车数据 id
        + 那可以把购物车 id 转成 dishId, setmealId
        + 于是关联关系表存 orderId + dishId + setmealId, 不过没存 dishFlavor, 可以用 shoppingCartIdList 查出来

#### 订单支付

1. 展示订单信息
    * GET + `/user/order/{id}`
      - 不过哪来的 orderId ?
      - 上次 POST 订单后 Result.success 返回订单信息 / id?? (我觉得可以)
      - 或者 GET + `/user/order/latest`, 查出该用户最新的那一单
    * OrderItemVO(不完整)
      - id + timeLeft + orderIdNumber + totalAmount
2. 展示支付方式
   * GET + `/user/order/payment/list`
   * List< PaymentVO > = id + name / type
   * 会不会有前端支付框架，直接调 + 发后端信号就行??
3. 选择支付方式 + 支付
   * 正常操作是: 点击某个支付 → 点击支付 → 密码/指纹 → 该支付验证通过 → 发钱给店家 → 后端、前端刷新
   * 也是前端框架 + 把钱发过去后给后端发信号 POST `/user/order/pay/{orderId}`
   * 思路: 
     - 前端直到支付成功(钱发过来)才访问这个接口，然后后端把订单状态设置为已支付
     - 再把购物车数据删除

#### 下单成功界面

1. 我觉得是展示订单状态 - 下单成功 / 下单失败
   * GET + `/user/order/{id}/status`
   * OrderStatusVO = id + status + period(前端展示预计多久送达)

2. 查看订单(查看单个??)
   * GET + `/user/order/{id}`
   * OrderVO(完整 VO) = id + orderIdNumber + payStatus(支付状态) + totalAmount + 
     - List< ShoppingCartVO >(需要展示相关商品数据) + createTime + isFinished(收货状态) + 
     - addressBookVO(地址、收货人、联系方式)



### 数据库表

1. order

   ```mysql
   create table if not exists order (
       id bigint primary key auto_increment comment '主键',
       order_number varchar( 40 ) unique not null comment '单号',
       user_id bigint not null comment '用户 id',
       address_book_id bigint not null comment '订单地址 id',
       payStatus tinyint not null comment '支付状态: 1 支付成功 0 未支付 -1 支付错误',
       totalAmount decimal not null comment '总金额 = 商品总价 + 打包费 + 配送费',
       is_finished tinyint not null comment '是否收货: 1 收货 0 未收货 -1 发货状态错误',
       create_time datetime not null default current_timestamp comment '创建订单时间',
       period varchar( 30 ) not null comment '期望时间段',
       INDEX idx_order_user_id user_id,
       INDEX idx_order_order_number order_number
   ) comment '订单表';
   ```

2. order_detail

```mysql
create table if not exists order_detail (
    id bigint primary key auto_increment comment '主键',
    dish_id bigint not null comment '关联菜品 id',
    dish_flavor varchar( 30 ) not null comment '关联菜品的口味',
    setmeal_id bigint not null comment '关联套餐 id',
#     不需要审计字段
    INDEX idx_order_detail_dish_id dish_id,
    INDEX idx_order_detail_setmeal_id setmeal_id
) comment '订单关联菜品套餐';
```
