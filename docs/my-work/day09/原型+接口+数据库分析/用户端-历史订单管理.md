## 用户端-历史订单管理

### 业务分析

1. 个人中心 → 历史订单，进入界面
    * 选择 3 种类型: 全部订单、待付款、退款
2. 展示内容
    * 下单时间(各订单按下单时间倒序排列)
    * 订单状态(待付款、待接单、已接单、派送中、已完成、已取消)
    * 菜品/套餐图片、名称、总金额、订单关联 Food 数量
    * `再来一单`
    * `去支付`(如果是 `待付款` )
3. 点击查看订单详情
    * 订单状态
        - 不管什么状态，都展示 `再来一单`
        - 订单已完成: 展示 `申请退款`, `再来一单`
        - 订单已取消: 只展示 `再来一单`，过一会儿 `订单已退款`
        - 派送中: 展示 `取消订单`, `再来一单`
        - 待接单: 展示 `取消订单`, `催单`, `再来一单`
        - 待付款: 展示 `取消订单`(请在 15 分钟内完成支付，超时将取消订单), `立即支付`, `再来一单`
    * 订单关联 Food
        - 图片、名称、单价、数量
    * 打包费、配送费、合计
    * 期望配送时间
    * 地址簿(收货人、电话中间4位星号、具体地址)
    * 订单号
    * 下单时间
    * 支付方式
    * 备注
    * 餐具数量选择
4. 取消订单: 
   * 待支付、待接单状态下，可直接取消订单
   * 已接单、派送中，不能直接取消订单、需要 `沟通商家`
   * 待接单(已支付)取消订单 → 退款
   * 取消订单 → 修改订单状态、支付状态


### 相关接口

1. 查询所有订单
    * GET + `/user/order/list`
    * List< OrderHistoryVO >
        - OrderHistoryVO = List< OrderDetailVO > +
            * id + orderTime + status + totalAmount + totalNumber 物品总数量
        - OrderDetailVO = id + image + name + amount + number 份数 + dishId + dishFlavor + setmealId
    * 思路: 查询该用户的所有订单，根据订单 id 查询关联数据，然后组装返回
2. 查询待付款订单
    * GET + `/user/order/pendingPayment/list`
    * List< OrderVO >
    * 思路: 查询 `status = 待付款` 的订单
3. 查询退款订单
    * GET + `/user/order/refund/list`
4. 查看订单详情
    * GET + `/user/order/{id}`
    * OrderVO = OrderDetailVO +
      * id + number + orderTime + packAmount + totalAmount + payment + remark +
      * tablewareStatus + tablewareNumber + expectedDeliveryTime +
      * addressBookId + consignee + phone + address
        - OrderDetailVO = id + image + name + amount + number + dishId + dishFlavor + setmealId
5. 再来一单
    * 想法一: 前端只传订单 id，后端自己找关联数据
    * POST + `/user/order/again/{id}`
    * 思路: 查该订单关联的 orderDetail, 拿到 dishId, setmealId 再查数据，检查是否停售，然后生成新的 orderDetail、order 返回前端
    * Result< OrderSubmitVo >
    * 想法二: 前端把那一堆关联菜品/套餐传过来
    * POST + `/user/order/again` + @RequestBody OrderAgainDTO
    * OrderAgainDTO = id + List< ShoppingCartDTO >
        - ShoppingCartDTO = dishId + dishFlavor + setmealId
        - 创建购物车
6. 取消订单
   * 我想的话: 
     - 不同状态不同反应
     - 待支付/待接单 → 取消订单 → 前端填写取消原因 → 取消
     - 已接单/派送中 → 取消订单 → 前端提醒联系商家 → 商家后台取消
     - 后者我觉得交给前端处理就行，主要是前者
   * POST + `/user/order/cancel`
   * OrderCancelDTO = id + cancelReason
