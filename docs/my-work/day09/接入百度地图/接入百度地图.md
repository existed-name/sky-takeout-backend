## 教程要求

1. 优化用户下单功能，加入校验逻辑，如果用户的收货地址距离商家门店超出配送范围（配送范围为5公里内），则下单失败。

2. 提示：

   1. 基于百度地图开放平台实现（https://lbsyun.baidu.com/）

   2. 注册账号--->创建应用获取AK(服务端应用)--->调用接口

3. 相关接口

   https://lbsyun.baidu.com/index.php?title=webapi/guide/webservice-geocoding

   https://lbsyun.baidu.com/index.php?title=webapi/directionlite-v1

4. 商家门店地址可以配置在配置文件中，例如：

   ~~~yaml
   sky:
     shop:
       address: 北京市海淀区上地十街10号
   ~~~


## 先去百度看看

1. 地理编码网址 → https://lbsyun.baidu.com/docs/webapi?title=geocoding/guide/webservice-geocoding-base
2. 需要认证个人开发者
3. 去控制台创建 AccessKey → https://lbsyun.baidu.com/apiconsole/key
    * 应用类型选 `服务端`
    * IP 白名单直接全部 `0.0.0.0/0`
4. ApiFox 发送请求
    * `GET https://api.map.baidu.com/geocoding/v3/?address=北京市海淀区上地十街10号&output=json&ak=您的ak`
    * 响应体
   
    ```json
    {
        "status": 0,
        "result": {
            "location": {
                "lng": 116.30787799999993,
                "lat": 40.05702706489032
            },
            "precise": 1,
            "confidence": 100,
            "comprehension": 100,
            "level": ""
        }
    }
    ```

    * 估计有用的是

    ```text
    lng  float  经度值
    lat  float  纬度值
    ```

5. 结合业务场景
    * `用户的收货地址距离商家门店超出配送范围（配送范围为5公里内）`
    * 也就是把收货地址拿到经纬度、门店地址拿到经纬度、然后粗略计算直线距离
    * 再调查百度地图有没有直接的计算 2 点距离的工具
    * 于是找到了[百度地图路线规划服务](https://lbsyun.baidu.com/docs/webapi?title=directionv2/direction-api-v2)
    * 应该是骑车送货、所以 → https://lbsyun.baidu.com/docs/webapi?title=directionv2/webservice-direction/cycling
    * `GET https://api.map.baidu.com/direction/v2/riding?origin=40.01116,116.339303&destination=39.936404,116.452562&ak=您的AK`

## 初步思路

1. 微信小程序用户记录准确地址
    * 记录了城市名称 city 更好
2. 下单的时候
    * 调百度地图、把商家位置进行地理编码（之后也可以缓存起来、或者直接写进常量）
    * 给用户地址地理编码
    * 然后再规划路线
    * 拿到 result.routes 的所有 distance
    * 如果 min( distances ) > 5km, 那就不能下单、提醒用户
