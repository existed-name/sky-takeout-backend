## 实现思路

1. 销售量的计算方式
    * orders 表没有专门的销售量记录字段、需要单独统计
      - 并且 orders 并不记录菜品、套餐
      - 还是要看 order_detail 
    * 看销量 → 订单 → 而且是卖出去的订单
      - 已取消的订单其实包括了卖出去但是退款的情况
      - 这里暂时只考虑正常的 COMPLETED 状态
    * 于是就找 COMPLETED 状态的订单
      - 拿到 id
      - 再找关联的 order_detail
      - 拿到里面的 number 数量、name 菜品/套餐名字
      - 注意 name 字段可能过时了
        * 实际我觉得应该拿到 dish_id、setmeal_id 去查实时 name, 
        * 这里先简单处理为查 name
      - 然后汇总
    * 整理下其实是筛选出已完成的订单对应的详情
      - 然后再按照菜品/套餐 id 或者 name 分组
      - 同时统计 number 数量

        ```mysql
        SELECT name, sum( number ) AS saleCount
        FROM order_detail
        WHERE order_id IN (
            # 筛选已完成的订单
            SELECT id
            FROM orders
            WHERE status = #{status}
        )
        GROUP BY name;
        ```
        
      - 缺点是改了名字后、这里旧名字跟新名字不能合并
      - 总不能不准人家修改 name
    * 也可以分别用 dish_id, setmeal_id 来分组、统计
      - 再 2 次查出对应的 name
      - 拼装 name, saleCount
      - 如果修改了菜品/套餐名、那这里也可以同步 name
      - 但缺点是查太多次数
    * 于是思考有没有更好的方法
      - 联表查询, 把 dish, setmeal 的 name 字段跟 order_detail 混合, 就可以确保 name 是最新的 name
2. 完整 SQL
    * v1

    ```mysql
    SELECT name, sum( number ) AS saleCount
    FROM (   
        (
            # 从订单详情晒出需要的字段
            SELECT dish_id, setmeal_id, number
            FROM order_detail
            WHERE order_id IN (
                # 筛选已完成的订单
                SELECT id
                FROM orders
                WHERE status = #{status}
            )
        ) AS temp_detail
        LEFT JOIN ( # LEFT JOIN 保留订单详情的字段
            SELECT id, name
            FROM dish
        ) AS temp_dish
        ON temp_detail.dish_id = temp_dish.id
        # 把 3 张表合并, 取核心的 name 菜品/套餐名、number 销售数量
        LEFT JOIN (
            SELECT id, name
            FROM setmeal
        ) AS temp_setmeal
        ON temp_detail.setmeal_id = temp_setmeal.id
    ) AS temp
    GROUP BY name;
    ```
   
    * v2, 查资料有一个 coalesce 合并函数可以选取非空字段

    ```mysql
    GROUP BY name;
    ```

    * v3: 问 ai,

      - 最后跟上 group by

    ```mysql
        COUNT(*) AS cnt
    ```
