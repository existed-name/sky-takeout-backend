## 教程给出了业务规则

* 营业额指订单状态为已完成的订单金额合计
  基于可视化报表的折线图展示营业额数据，X轴为日期，Y轴为营业额
  根据时间选择区间，展示每天的营业额数据


## 初步思路

1. 可以暂时把 1 天作为最小单位, 多次查询某天数据汇总成列表
2. 再思考, 可以查询某个时间范围的订单
    * 把日期作为分组条件( 只取月、日 )
    * 选择需要的 amount 字段
    * 分成 1 个日期 → 1 批 amount 的表格
    * 然后分别统计求和该日期的总金额
    * 最后得到 日期 → 当天总金额 的列表
    * `List< Map< String, BigDecimal > >` Map 只装了 1 组数据( 也就是 Entry )
    * 或者整个 Map 装了所有组的数据
3. sql 写法大概是

    ```mysql
    select sum( amount ), order_time
    from orders
    where order_time <= #{end} and order_time >= #{begin}
    group by order_time
    ```

## 接口设计

1. 我觉得前端应该传 `beginTime, endTime`
    * 装进`AmountStatisticsDTO` 传给后端
2. 后端输出 `AmountStatisticsVO`
    * 日期跟当天营业额应该捆绑在一起
    * `List< Map< String, BigDecimal > >`
    * 个人觉得比分成 2 个 List< Object > 更清晰、内聚
    * 问了 ai 后想起来可以直接把 1 组数据包装成对象, `List< xxxCount >`
3. 接口路径
    * 语义: 管理端、查看营业额应该算是公共接口或者店铺管理相关内容吧
    * GET + `/admin/shop/amount-stat`

## 整理思路

* 看完教程接口设计, 结合 ai 建议 + 自己的思路
1. 接口路径 `/admin/report/turnover-statistics`
2. 前端入参 `?begin=&end=`
    * 检验格式 `2022-05-01`
3. 主要靠 sql 查询
4. 后端出参 `TurnoverVO`
    * 包装 `List< TurnoverItemVO >`
    * `TurnoverItemVO` = date + turnover
