## {id} 为非正数不会触发 `@Positive` 检验

1. 明明有 `@Positive` 但是我传 0、-1 报错 `订单不存在` 而不是检验 id

    ```java
        @ApiOperation( "查询订单详情" )
        @GetMapping( "/{id}" )
        public Result< AdminOrderInfoVO > getInfo(
                @PathVariable( name = "id", required = true )
                @Positive( message = "订单 id 必须是正整数" )
                Long id
        ){}
    ```

2. 如果 id = null 那么不会经过 `@Positive`
    * 但是我传的数据非 null
    * 而且 `@PathVariable` 显示指定必填


## 对于以上情况

1. 考虑过顺序问题
    * Controller 出现在前面的端点会被优先检测到, 可能会一部分干扰查询订单详情、条件分页查询
    * 不过把查询订单详情放到最前面测试没变化
2. 问 AI
    1. 除非显式传 dto = null, 否则 Spring 会自己 new dto, 所以条件分页查询的 dto `@NotNull` 没用
    2. Controller 内部方法出现单参数检验注解时, 需要给 Controller 注释 `@Validated`
       * `@Valid` 放在 dto 参数上面、检验 dto 里面没有分组的字段、如果有嵌套 dto 也可以检验
       * `@Validated` 也可以放在 dto 参数上面、主要在区分分组的时候用
