## 测试 2 点之间距离, 返回 data.distances 为空列表, 以及延申的参数错误问题

1. 问题描述
    * 测试接口 `/test/baidu-map/distances?origin=&destinatination=`
    * 传入 `北京市`, `上海市` 想要获取 2 点之间各路线的距离
    * 然而返回的距离列表为空

        ```json
        {
            "code": 1,
            "msg": null,
            "data": {
                "distances": []
            }
        }
        ```

2. 查看 `DirectionDTO` 目前只有

    ```java
    /** 2 地址之间各种路线的距离 */
    private List< Double > distances = new ArrayList<>();
    ```

    * 于是补上状态码、消息, 看看是什么情况

    ```java
        /** 响应状态码 */
        @JsonProperty( "status" )
        private Integer status;
        /** 状态码对应的信息 */
        @JsonProperty( "message" )
        private String message;
    ```
   
    * 同时解析 json 时指定这 2 个字段( 这里用的 json 树节点读取数据 )

    ```java
        directionDTO.setStatus( rootNode.path( "status" ).asInt() );
        directionDTO.setMessage( rootNode.path( "message" ).asText() );
    ```
   
3. 发现是参数有问题

    ```json
    {
        "code": 1,
        "msg": null,
        "data": {
            "distances": [],
            "status": 2,
            "message": "参数错误"
        }
    }
    ```

4. 再手动测百度地图 API
    * 发现也是参数错误
    * 但这里的坐标我记得我好像输入的 `精度,纬度` 也就是精度、纬度顺序搞反
    * 测试百度地图示例网址是没问题的的
    * 初步怀疑可能是我内部把精度、纬度拼接字符串时搞反顺序
5. 首先定位到 `com.sky.external.GeoCodingDTO.concatLongitudeAndLatitude`
    * 然而拼接时是正确的 `纬度,精度` 顺序
    * 并且逗号也是英文半角
6. 那再跟着 service 看看逻辑
    * 先看到 `directByGeoCodingDTOs` 调用 `directByGeoCoordinates` 时传参顺序反了
    * 但起点终点交换顺序不影响、而且改成 origin 在前 destination 在后后依然是参数错误

    ```java
        public DirectionDTO directByGeoCodingDTOs( GeoCodingDTO originGeoCodingDto, GeoCodingDTO destinationGeoCodingDto ){
            String destination = destinationGeoCodingDto.concatLongitudeAndLatitude();
            String origin = originGeoCodingDto.concatLongitudeAndLatitude();
            return directByGeoCoordinates( destination, origin );
        }
    ```

7. 继续排查 `BaiduMapUtil.directByGeoCoordinates` 方法
    * 暂时认为只能是拼接/设置 uri / 参数时出错

    ```java
    /*
        请求路径、请求参数、发起请求、解析响应
     */
    String directionUrl = baiduMapProperties.getUrl().getDirection();
    Map< String, String > requestParamsMap = Map.ofEntries(
            Map.entry( "origin", origin ),
            Map.entry( "destination", destination ),
            Map.entry( "ak", baiduMapProperties.getAccessKey() )
    );
    
    String responseJson = HttpClientUtil.doGet( directionUrl, requestParamsMap );
    DirectionDTO directionDTO = new DirectionDTO();
    // ...
    ```
   
    * 看几遍 map 设置的硬编码 key, 没写错
    * application.yaml 也设置了 url 能对上 baiduMapProperties 的字段
    * map.ofEntries 虽然是不可变 Map、但是这里只读不会涉及 put, 而且地理编码功能也是 Map.ofEntries 一样可以用
8. 另一个假设
    * 如果 2 地距离太远、不在国内, 可能会被拒绝
    * 我直接去掉小数点后面的部分、北京 `39,116` 上海 `31,121`
    * 然而它会真的提示距离太远、不会提示参数错误

    ```json
    {
        "status": 2002,
        "message": "距离超出限制，无可用骑行路线"
    }
    ```

9. 看不出来规律, 临时让 utils 包打印 debug 日志

    ```yaml
    logging:
      level:
        com:
          sky:
            mapper: debug
            service: info
            controller: info
            utils: debug
    ```

    * 测试 `北京市海淀区`, `北京市雄安新区`
   
    ```text
    2026-09-07 10:14:22.695 DEBUG 45428 --- [nio-8080-exec-2] 
    com.sky.utils.HttpClientUtil             : 
    GET 请求执行成功, uri = https://api.map.baidu.com/direction/v2/riding?destination=115.889%2C38.734241&origin=116.305435%2C39.965488&ak=我的ak, 
    响应结果字符串 = {"status":2,"message":"参数错误"}
    ```

    * `destination=115.889%2C38.734241`, `origin=116.305435%2C39.965488`
    * 为啥子 origin, destination 参数里面会有乱码 → `%2C` 是英文逗号
    * `115,38` 明显是 `经度,纬度` 而不是 `纬度,经度`, 也就是还是写反了
10. 最终确认: 就是写反了拼接顺序
    * `com.sky.external.GeoCodingDTO.concatLongitudeAndLatitude`
    * 容易搞混单词: 纬度是 latitude、经度是 longitude, 地理坐标 `( 纬度 lat, 经度 lng )`
