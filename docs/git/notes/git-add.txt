:: ============
:: 常用的 git add 命令
:: 作用: 将工作区的修改添加到暂存区(staging area)
:: ============

:: 【最常用】添加当前目录下所有修改(新增 + 修改，不包括删除)
git add .

:: 添加所有修改(新增 + 修改 + 删除)，等同于 git add --all
git add -A

:: 【只添加已跟踪】文件的修改和删除(不包括新增未跟踪文件) = git add --update
git add -u

:: 添加指定文件
git add <文件路径>

:: 添加多个指定文件
git add <文件1> <文件2>

:: 强制添加被 .gitignore 忽略的文件(慎用)
git add -f <文件路径>

:: 交互式添加: 进入交互模式，可选择性添加文件或分块(hunk)
git add -i

:: 分块添加: 对文件的修改逐块确认是否添加(适合只想提交部分修改的场景)
git add -p <文件路径>

:: 模拟运行: 显示会添加哪些文件，但不真正添加
git add -n .

:: 显示详细添加信息
git add -v .


:: ============
:: 常用组合场景
:: ============

:: 场景1: 日常开发提交前，添加所有改动
git add .

:: 场景2: 只想提交已跟踪文件的修改，忽略新增文件(如临时测试文件)
git add -u

:: 场景3: 修改了多个功能，只想提交某个文件的部分修改
git add -p <文件路径>

:: 场景4: 误删了文件想恢复并添加到暂存区
git add -A

:: 场景5: 确认哪些文件会被添加(不真正执行)
git add -n .


:: ============
:: 查看添加后的状态
:: ============
git status
