## 说明

1. 不知道为什么我个人追求所谓的 `最佳实践`
    * 每段代码都要问问 AI 怎么样、规不规范
    * 包括写代码考虑很久、很多，可以看到一堆防御式编程，但似乎没有🥚用
    * 可能还是完美主义情结
2. 这里的几个文件就是当时( 五六月份 )整理的提示词
    * [AI-Prompt](/docs/prompt/AI-Prompt.md): 喂给 AI 插件（通义灵码/Copilot）或者 Agent 让他看看我的代码、对比教程操作
    * [rules](/docs/prompt/rules.md): 约束文档（后来也是做成了自己的 SKILL）

## 个人感受

1. 客观来说, 写一个功能点、让 AI 对照教程和他的训练数据评价, 确实改正了一些规范, 然后也从 AI 那里学到了一些操作，像 MapStruct 就是从 AI 那里问出来、然后一步一步研究写法、再在项目各处使用的
2. 而缺点则是会付出更多的时间去研究哪里规不规范、需不需要优化，对于学习期可能不太友好，因为我现在觉得教程的核心是体验写代码中可能遇到的（业务/技术）场景、对后端项目有个概念，真正的规范要去厂/各种团队里面才能接触到
3. 那么我现在觉得，时间相对充足、但不算非常充足的情况下，可以先看看只靠自己能不能写出来（尤其是写下思路分析） → 不能的话就手敲教程的代码 → 一直尝试自己写代码，然后再对比教程，写下自己认为教程可能有问题的地方，甚至问 AI、知道这个地方怎么写更好、但不一定完全按照规范来写代码 → 等到中后期熟练后，再来考虑规范的问题
